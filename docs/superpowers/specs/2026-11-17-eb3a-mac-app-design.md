# EB3A Monitor для macOS — дизайн

Дата: 2026-11-17. Статус: на погодження.

## Навіщо

Власник EB3A живе з блекаутами і сонячною панеллю. Дві речі він дивиться найчастіше:
1. **У блекаут:** скільки заряду лишилось (і на скільки вистачить).
2. **Вдень:** скільки потужності зараз дає сонце.

Офіційним додатком Bluetti майже не користується. Хоче нативний Mac-застосунок: цифри в рядку меню, віджет, трохи статистики.

## Цілі

- Рядок меню: живі заряд і сонячна потужність, оновлення ~кожні 2 с.
- Без мережі (блекаут): рядок меню показує заряд і прогноз автономності.
- Поповер по кліку: детальний стан, графік за добу, перемикачі.
- Віджет WidgetKit (робочий стіл / Центр сповіщень): заряд, сонце, мережа.
- Постійне BLE-з'єднання, автоперепідключення, автозапуск при вході.

## Не-цілі (v1)

- iOS-версія, сповіщення, експорт історії, кілька станцій одночасно.
- Робота під час сну Mac (BLE рветься — історія матиме пропуски, це ок).
- Дослідницькі функції (сирі запити, скани) — для цього лишається `live.py`.

## Анти-цілі (провал, навіть якщо «працює»)

- Будь-який запис поза перевіреним списком. **Ніколи** не писати 3060 (вимкнення), 3006, 3015/3016, нічого в OTA-сервіс `1d14d6ee-…`.
- Застосунок, що вимагає відкритого Terminal/Python.
- Випадкове вимкнення AC-виходу в блекаут (навантаження зникне).
- Цифри, яким не можна вірити: показувати «—», коли даних немає або вони застарілі, а не останнє значення як живе.

## Обмеження та факти протоколу

Повна карта: `REGISTERS.md` (у корені репо). Ключове:
- BLE GATT: сервіс `0000ff00-…`, write `ff02`, notify `ff01`. Шифрування немає (ARM 2063.03 / DSP 2052.11).
- Modbus RTU: FC03 читання, FC06 запис (відповідь — ехо 8 байт). CRC16 Modbus (0xA001), little-endian.
- Валідні **стартові** адреси: 1–210, 1080–1082, 3000–3077; від старту можна читати далі. Довгі блоки працюють (інші проєкти читають 10×53).
- Невалідний старт → exception `01 83 02 C0 F1` — не парсити як дані.
- Відповідь може приходити кількома notify-пакетами — збирати до `5 + byteCount` (або 5 байт для exception, 8 для запису).
- Одне з'єднання: поки Mac підключений, офіційний додаток не підключиться (прийнятно).

Поля для застосунку:

## Підходи (розглянуті)

- **A. Нативно Swift (обрано).** Menu bar app на SwiftUI + CoreBluetooth, віджет WidgetKit, обмін через App Group. Один процес, свій дозвіл Bluetooth, автозапуск.
- B. Python `live.py` як бекенд + тонкий Swift-клієнт по HTTP. Швидший старт, але два процеси і Bluetooth лише через Terminal — крихко для «постійно у фоні».
- C. SwiftBar + Python. Годину роботи, але без віджета — не відповідає вимогам.

Власник обрав A: застосунок має жити у фоні роками і не залежати від терміналу в блекаут.

## Дизайн

### Структура

Xcode-проєкт у `mac/` поруч із Python-інструментами. Цілі:
- **EB3AKit** (Swift package або framework, без UI): протокол (кадри, CRC, збирання відповідей), модель `StationState`, декодування регістрів, прогноз автономності. Покривається юніт-тестами на реальних кадрах із `logs/`.
- **EB3AMonitor** (app, `LSUIElement` — без іконки в Dock): BLE-менеджер, `MenuBarExtra`, поповер, запис історії, оновлення віджета, автозапуск (`SMAppService`).
- **EB3AWidget** (WidgetKit extension): читає знімок стану з App Group.

### BLE

- Перше підключення: скан за іменем `EB3A*`, запам'ятати `identifier` пристрою. Далі — підключатися до нього напряму; якщо зник — знову скан.
- Тримати з'єднання постійно. На розрив / пробудження Mac — перепідключення з наростаючою паузою (1 → 30 с).
- Цикл: 4 читання підряд, далі пауза до 2 с від початку циклу. Записи (команди) — у черзі між читаннями.
- Таймаут відповіді 3 с; 3 таймаути поспіль → розірвати й перепідключитися.
- **«Звільнити станцію»** (поповер): відключитись і не перепідключатись, доки користувач не натисне «Підключитись» — щоб `live.py` чи офіційний додаток могли взяти з'єднання *(рішення Claude)*. Стан паузи зберігається між перезапусками.

### Рядок меню

- Джерела + заряд (змінено власником 17.11: прогноз прибрано з бару, додано джерело): `⚡ ☀ 142W  🔋 87%`; ⚡ — мережа є, ⚡✕ — немає; ☀ з W, коли 44 = 1.
- Прогноз автономності — лише в поповері.
- Немає з'єднання / дані старші 30 с: `🔋 —` і сірий значок.

### Прогноз автономності

- Чиста потужність батареї `P = (38 + 39) − (36 + 37)`; плюс — розряд.
- Згладжування: експоненційне середнє з вікном ~5 хв.
- Залишок = `заряд% × ємність × коеф / P`, де ємність 268 Wh, коеф. корисної ємності 0.9 (константа в коді, легко змінити).
- Показувати лише коли P > 5 W; інакше нічого. Формат `~Г:ХХ`.

### Поповер

- Заряд великим + стан (заряджається / розряджається / pass-through) + прогноз, якщо розряд.
- Сонце: W, V панелі, «заряджає» (46).
- Мережа: є/нема, V, W.
- Виходи: AC W, DC W.
- Графік за 24 год (Swift Charts): заряд % і сонце W.
- Перемикачі: AC, DC, ліхтар (4 режими), режим заряду (3), ECO + таймер, power lifting.
  - **Вимкнення AC — з підтвердженням**, якщо мережі нема.
  - Після команди кнопка в стані «…», доки регістр не підтвердить нове значення (типово ~240 мс), або помилка через 3 с.
- Внизу: стан з'єднання, «Запускати при вході» (перемикач), «Вийти».

### Історія

- Раз на хвилину — запис агрегату: середні 36/37/38/39, заряд, прапорці 45/46. Зберігати 7 днів.
- Сховище в контейнері App Group (SQLite або файл JSON Lines — вибір будівельника; обсяг ~10 тис. рядків).

### Віджет

- Розміри small і medium.
- Small: заряд великим, під ним ☀ W або ⚡✕ + прогноз.
- Medium: + міні-графік заряду за 24 год, мережа, AC/DC вихід.
- Дані: знімок `StationState` + час у App Group. Якщо знімок старший 10 хв — показувати «немає даних».
- Оновлення: застосунок викликає `WidgetCenter.reloadAllTimelines()` при значущих змінах (заряд ±1%, мережа з'явилась/зникла, сонце ±20 W), не частіше ніж раз на хвилину. Реальна частота залежить від бюджету системи — перевірити на практиці.

### Підпис

- **Безкоштовний Personal Team** (рішення власника), Team ID `<TEAM_ID>`. Платної підписки немає.
- Entitlements: App Sandbox, Bluetooth, App Group з префіксом Team ID (`<TEAM_ID>.eb3a`, macOS-стиль, не `group.`).
- `NSBluetoothAlwaysUsageDescription` в Info.plist.
- **Ризик:** віджет + App Group на безкоштовній команді можуть не працювати. Тому віджет — **останній етап**. Якщо не вийде: власник вирішує, чи брати платну підписку ($99/рік); застосунок у рядку меню від цього не залежить.

### Порядок робіт

1. EB3AKit + тести.
2. Застосунок у рядку меню: BLE, рядок меню, поповер, перемикачі (AC — після ручної перевірки запису 3007 на станції).
3. Історія + графік.
4. Віджет (з ризиком підпису).

### Тестування

- EB3AKit: CRC (еталон `01 03 00 00 00 01` → `84 0A`), збирання фрагментованих відповідей, exception-кадри, запис-ехо, декодування на реальних кадрах із `logs/`/`dumps/`, прогноз автономності.
- Ручна перевірка на станції: з'єднання, перепідключення після сну, команди, віджет.
